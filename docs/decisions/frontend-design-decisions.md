## プロダクトビジョン

> **「日常の隙間に、収容違反を」**
>
> 普段の生活に追われ昔みたいにSCPを追えなくなった人に、推薦という機能で新たな出会いと刺激をもたらす。

## トレードオフ分析

| 観点                 | 選択肢A              | 選択肢B               | 決定     | 理由                             |
| -------------------- | -------------------- | --------------------- | -------- | -------------------------------- |
| 推薦UI               | スワイプ（Tinder風） | 無限スクロール        | **B**    | WebViewとジェスチャー干渉を回避  |

## 決定事項サマリー

### 基本方針

1. **没入型UI**: 全画面WebView + シームレス無限スクロール
2. **ミニマル操作**: ボタンは最小限（お気に入り、次へ）
3. **暗黙的フィードバック**: スクロール深度 + 滞在時間でinterest_level算出（skip/neutral/like）
4. **段階的オンボーディング**: 初心者向けパック選択 + 熟練者向けSCP番号指定

### UIレイアウト

```
┌─────────────────────────────────────┐
│ SCP-173                    [次へ →]│ ← 自動非表示ヘッダー
├─────────────────────────────────────┤  （スクロールで隠れる）
│                                     │
│                                     │
│        [全画面 WebView]             │
│                                     │
│        シームレスに次記事へ続く     │
│        ↓                            │
│        タイトル自動更新             │
│                                     │
└───────────────────────────────[♡]──┘
                              ↑ お気に入りのみ
```

### 技術的制約

- Next.js App Router（vidmarkアーキテクチャ準拠）
- Hono RPC経由でバックエンドAPI連携
- iframe contentWindow直接アクセスでスクロール位置検知（wiki-proxy同一オリジン）
- WebView内ジェスチャーとの干渉を避けた設計

### MVPスコープ

**含む:**

- オンボーディング（パック選択 + SCP番号指定カスタム）
- 記事閲覧（全画面WebView + 無限スクロール）
- お気に入り一覧（一覧表示、再読、解除）
- 自動非表示ヘッダー（タイトル + 次へボタン）
- フローティングお気に入りボタン

**含まない（将来対応）:**

- 検索機能
- 設定画面
- 履歴一覧
- プロフィール
- エッジスワイプによるスキップ
- お気に入りの並び替え/フォルダ分類

### エッジケース対応

| ケース         | 対応                       |
| -------------- | -------------------------- |
| 推薦記事切れ   | 再オンボーディング提案     |
| 読み込みエラー | シンプルなエラーメッセージ |

## UI詳細仕様

### オンボーディングフロー

```
┌─────────────────────────────────────┐
│  ようこそ！                         │
│                                     │
│  どちらの方法で始めますか？         │
│                                     │
│  ┌─────────────────────────────┐   │
│  │  🎁 スターターパックから選ぶ │   │ ← 初心者向け
│  └─────────────────────────────┘   │
│                                     │
│  ┌─────────────────────────────┐   │
│  │  🔢 好きなSCPを教える       │   │ ← 熟練者向け
│  └─────────────────────────────┘   │
│                                     │
└─────────────────────────────────────┘
```

**スターターパック選択（初心者向け）:**

- 事前定義されたパック（ホラー、SF、コメディ等）から選択
- 1〜2画面で完了

**SCP番号指定（熟練者向け）:**

- 好きなSCP番号を複数入力（例: SCP-173, SCP-682, SCP-999）
- 入力されたSCPのEmbeddingを平均化して初期嗜好ベクトルを生成
- 類似記事を推薦

### 記事閲覧フロー

1. WebViewで記事を全画面表示
2. スクロールでヘッダーが自動非表示
3. 上スクロールでヘッダー再表示
4. 記事最下部到達でも自動遷移しない（ユーザーが「次へ」を押すまで現在の記事を表示）
5. スクロール位置に応じてヘッダータイトルが自動更新
6. 「次へ」ボタン = Skip + メタデータ（scrollDepth, dwellTime, interest_level）として記録
7. お気に入りボタン = Like として記録
8. スクロール深度と滞在時間から暗黙的にinterest_level（skip/neutral/like）を算出

### お気に入り一覧

- 保存した記事をリスト表示
- タップで記事を再読（WebView表示）
- スワイプまたはボタンでお気に入り解除
- MVP後: 並び替え、フォルダ分類、外部共有

## 設計変更履歴

### 2026-02-11: フィードバックモデル変更

**変更前**: 読了（最下部到達）= 暗黙的Like、「次へ」ボタン = Dislike
**変更後**: 「次へ」ボタン = Skip + メタデータ（scrollDepth, dwellTime, interest_level）、お気に入り = Like

- 明示的Dislikeを廃止し、スクロール深度と滞在時間から暗黙的にinterest_level（skip/neutral/like）を算出
- 読了自動遷移を廃止。遷移は「次へ」ボタンタップのみ
- 詳細: `specs/006-frontend/006-05-transition-ux/006-05.md` の仕様変更履歴を参照

### 2026-02-16: wiki-proxyアーキテクチャ変更（printer--friendly → DOM抽出方式）

**変更前**: SCP Wikiの `printer--friendly` URL（印刷用ページ）を取得し、正規表現でHTML加工
**変更後**: 通常ページを取得し、jsdomでDOM解析 → `#main-content` を抽出して再構築

- **背景**: printer--friendly モードでは記事固有のCSS（テーマ、装飾）とJS（インタラクティブ演出）が除外されていた
- **DOM抽出方式**: 通常ページをjsdomでパースし、`#main-content`（`#page-title` + `#page-content`）を抽出。記事固有の `<style>`, `<link rel="stylesheet">`, `<script>` を収集し、プラットフォームスクリプト（WIKIDOT.combined.js, OZONE等）のみフィルタリング
- **CSS !important戦略**: 可読性のための注入CSS（max-width, padding, font-size等）に `!important` を付与し、記事テーマCSSとの共存を実現
- **WIKIDOT stub注入**: 記事JSが参照する `window.WIKIDOT` グローバルオブジェクトのスタブを注入し、ReferenceError を防止
- **フロントエンドへの影響**: iframe内に記事固有テーマ・装飾JSが反映されるため、SCP Wikiの雰囲気がより忠実に再現される。スクロール検知（contentWindow直接アクセス）は変更なし
- 詳細: `apps/api-server/src/routes/wiki-proxy.ts`

### 2026-02-11: スクロール検知方式変更

**変更前**: Intersection Observer API / postMessage方式
**変更後**: iframe contentWindow直接アクセス方式

- wiki-proxy（`/api/wiki-proxy/...`）経由で同一オリジン配信されるため、iframe.contentWindowに直接アクセス可能
- postMessage方式のiframe側送信スクリプトは不要に
- 詳細: `specs/006-frontend/006-02-article-reader/006-02-02.md` を参照
