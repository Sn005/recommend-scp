## コスト構造の特徴

### スケーリングのボトルネック

```
DAU 100 → 500 :  Supabase Free→Pro への移行が最大の段差（+$25）
DAU 500 → 1,000:  Railway のCPU/メモリ増加（+$5）、ほぼ線形
DAU 1,000 → 5,000: Vercel Hobby→Pro 移行（+$20）+ Railway増加（+$16）
```

### なぜ安いのか

1. **Embedding生成がバッチ処理**: リアルタイムAPI呼び出しなし。推薦時はDB内のベクトル検索のみ
2. **推薦計算がDB側で完結**: pgvectorのRPC関数でベクトル類似度検索。APIサーバーのCPU負荷が低い
3. **ユーザーデータが軽量**: 嗜好ベクトル(6KB) + フィードバック履歴のみ。DBが肥大化しにくい
4. **記事データが固定**: 〜7,000件で安定。週次の差分更新はごく少数

### スケール時の注意点

| DAU     | 注意点                                                        |
| ------- | ------------------------------------------------------------- |
| 1,000+  | Railway のレスポンスタイム監視。Redisキャッシュ導入検討       |
| 3,000+  | Supabase接続プール（pgBouncer）の設定確認                     |
| 5,000+  | Vercel CDNキャッシュ戦略の最適化。Railway複数インスタンス検討 |
| 10,000+ | Supabase Pro → Team($599/月)検討。Railway Pro($20/月)への移行 |
