# Subtask: 記事詳細API著者情報追加

## 親Story

[014-03: 記事帰属表示](./014-03-article-attribution.md)

## ユーザーストーリー

**ペルソナ**: フロントエンド開発者
**目的**: 記事情報APIから著者名を取得する
**価値**: フロントエンドで帰属表示を実装するためのデータソースを確保する
**理由**: クライアントから直接DBにアクセスできないため、API経由でのデータ提供が必要であるから

> フロントエンド開発者として、記事情報APIから著者名を取得して、帰属表示に必要なデータを確保したい。なぜならクライアントから直接DBにアクセスできないため、API経由でのデータ提供が必要であるから。

## Acceptance Criteria

- [ ] WHEN フロントエンドが `GET /articles/:articleId/content` をリクエストした際
      GIVEN 記事に `author` 情報がDBに存在する場合
      THEN レスポンスに `author` フィールドが含まれる

- [ ] WHERE `GET /articles/:articleId/content` エンドポイント
      IF `author` が NULL の場合
      THE SYSTEM SHALL `author` を空文字列として返す

- [ ] WHEN エンドポイントでエラーが発生した際
      THEN 既存のエラー耐性動作を維持し `{ title: "", excerpt: "", author: "" }` を返す

## 設計

### 変更対象ファイル

1. **`apps/api-server/src/domains/articles/service.ts`**
   - `ContentResult` インターフェースに `author: string` を追加
   - `getContent()` メソッドでDBから `author` を取得

2. **`apps/api-server/src/domains/articles/repository.ts`**
   - `getArticleById()` のSELECTに `author` を追加（既存の場合）
   - または著者情報取得用のメソッドを追加

### レスポンス形式変更

```typescript
// Before
interface ContentResult {
  title: string;
  excerpt: string;
}

// After
interface ContentResult {
  title: string;
  excerpt: string;
  author: string; // 追加（NULL時は空文字列）
}
```

### 処理フロー

1. `articleId` でDBから `author` を取得
2. WikiからHTML取得・DOM解析（既存処理）
3. `title`, `excerpt`, `author` を返す
4. `author` が NULL の場合は `""` を返す

### 技術的考慮事項

- 既存の `getContent()` は WikiからHTMLフェッチしている
- DB問い合わせを追加するが、失敗してもエラー耐性を維持
- `article_id` カラム（TEXT）で検索（`id` はUUID型のPK）
