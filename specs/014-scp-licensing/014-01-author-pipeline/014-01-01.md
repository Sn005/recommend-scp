# Subtask: DBマイグレーション（authorカラム追加）

## 親Story

[014-01: 著者情報データパイプライン対応](./014-01-author-pipeline.md)

## ユーザーストーリー

**ペルソナ**: 開発者
**目的**: scp_articlesテーブルに著者情報を格納するカラムを追加する
**価値**: 帰属表示に必要な著者データの永続化基盤を構築する
**理由**: 著者情報の保存先がなければクローラーやAPIで利用できないから

> 開発者として、scp_articlesテーブルに著者情報を格納するカラムを追加して、帰属表示に必要な著者データの永続化基盤を構築したい。なぜなら著者情報の保存先がなければクローラーやAPIで利用できないから。

## Acceptance Criteria

- [ ] WHEN マイグレーションを実行した際
      GIVEN `scp_articles` テーブルが存在する場合
      THEN `author` TEXT カラム（NULL許容）が追加される
      AND 既存レコードの `author` は NULL である

- [ ] WHEN マイグレーションをロールバックした際
      GIVEN `author` カラムが存在する場合
      THEN `author` カラムが削除される

## 設計

### マイグレーションSQL

```sql
-- Up
ALTER TABLE scp_articles ADD COLUMN author TEXT;

-- Down
ALTER TABLE scp_articles DROP COLUMN IF EXISTS author;
```

### 技術的考慮事項

- NULL許容にする理由: 既存データにはauthorがないため、NOT NULL制約は不可
- インデックス不要: authorでの検索は想定しない
- RLSポリシー: 既存のscp_articles RLSポリシーでカバーされる
