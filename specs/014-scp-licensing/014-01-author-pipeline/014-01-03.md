# Subtask: 既存データバックフィルスクリプト

## 親Story

[014-01: 著者情報データパイプライン対応](./014-01-author-pipeline.md)

## ユーザーストーリー

**ペルソナ**: 開発者
**目的**: 既存のSCP記事データに著者情報を補完する
**価値**: 既存の全記事で帰属表示が可能になる
**理由**: マイグレーション時点では既存データの `author` が NULL であり、APIから取得して埋める必要があるから

> 開発者として、既存のSCP記事データに著者情報を補完して、既存の全記事で帰属表示が可能にしたい。なぜなら既存データの `author` が NULL であり、APIから取得して埋める必要があるから。

## Acceptance Criteria

- [ ] WHEN バックフィルスクリプトを実行した際
      GIVEN `scp_articles` に `author` が NULL のレコードがある場合
      THEN SCP Data APIから `creator` を取得し `author` を更新する
      AND 更新件数をログ出力する

- [ ] WHEN バックフィルスクリプトを実行した際
      GIVEN SCP Data APIで `creator` が取得できない記事がある場合
      THEN 該当記事をスキップしてログに記録する
      AND 他の記事の処理は続行する

- [ ] WHEN バックフィルスクリプトにドライランオプションを指定した際
      THEN DBへの更新を行わず、対象件数のみ表示する

- [ ] WHEN SCP Data APIから `creator` が空文字列として返却された際
      THEN `author` カラムに NULL を保存する（空文字列での保存は行わない）

## 設計

### スクリプト配置

```
scripts/backfill-author.ts
```

### 処理フロー

1. `scp_articles` から `author IS NULL` のレコードを全件取得
2. SCP Data APIのインデックスデータをフェッチ（`creator` フィールド含む）
3. article_idで突合し、`creator` → `author` にマッピング
4. バッチ更新（10件ずつ）
5. 結果サマリーをログ出力

### CLIオプション

```
--dry-run    DBに書き込まずに対象件数のみ表示
--batch-size バッチサイズ（デフォルト: 10）
```

### 技術的考慮事項

- SCP Data APIのレート制限に配慮してバッチ処理
- インデックスデータは一括取得（個別記事フェッチは不要）
- `scripts/` ディレクトリ内のため `console` 使用可
