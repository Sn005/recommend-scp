> システム管理者として、日本語版記事URLを効率的に管理し、多言語対応の拡張性を確保したい。なぜなら日本語クローラーを実装せずに、法則的にURLを生成したいから。

## 背景

### URL生成の法則性

| 記事種別       | URL パターン                           |
| -------------- | -------------------------------------- |
| 英語版の翻訳   | `http://scp-jp.wikidot.com/scp-173`    |
| 日本オリジナル | `http://scp-jp.wikidot.com/scp-173-jp` |

**法則:**

```
日本語版URL = 'http://scp-jp.wikidot.com/' + LOWER(article_id)
```

### 多言語拡張性

将来の言語追加時もスキーマ変更不要:

- 韓国語: `http://ko.scp-wiki.net/{article_id}`
- 中国語: `http://scp-wiki-cn.wikidot.com/{article_id}`

- [x] WHEN マイグレーションを実行した際
      THEN `lang` カラムにインデックスが作成される

- [x] WHEN マイグレーションを実行した際
      GIVEN 既存の `scp_articles` に英語版記事がある場合

      AND `article_translations` に挿入される

### AC-4: URL生成ロジック

- [x] WHEN 日本語URLが生成される際
      GIVEN article_id が "SCP-173" の場合
      THEN URL は "http://scp-jp.wikidot.com/scp-173" となる

## 技術設計

### テーブル定義

```sql
CREATE TABLE article_translations (
  article_id TEXT NOT NULL,
  lang TEXT NOT NULL,
  url TEXT NOT NULL,
  has_translation BOOLEAN DEFAULT NULL,
  checked_at TIMESTAMPTZ,
  PRIMARY KEY (article_id, lang),
  FOREIGN KEY (article_id) REFERENCES scp_articles(article_id)
);

CREATE INDEX idx_article_translations_lang
  ON article_translations(lang);
CREATE INDEX idx_article_translations_has_translation
  ON article_translations(lang, has_translation);
```

### 初期データ投入

```sql
INSERT INTO article_translations (article_id, lang, url)
SELECT
  article_id,
  'ja',
  'http://scp-jp.wikidot.com/' || LOWER(article_id)
FROM scp_articles
WHERE lang = 'en';
```
