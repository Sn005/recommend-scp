# Story: セキュリティヘッダー

## 親EPIC

[009: セキュリティ強化](../009-security.md)

## ユーザーストーリー

**ペルソナ**: システム運用者
**目的**: APIレスポンスに標準的なセキュリティヘッダーを付与する
**価値**: ブラウザのセキュリティ機能を活用し、XSS・クリックジャッキング等の攻撃リスクを低減する
**理由**: 現状のAPIレスポンスにセキュリティヘッダーが付与されておらず、ブラウザ側の保護機能が活用されていない

> システム運用者として、APIレスポンスに標準的なセキュリティヘッダーを付与して、ブラウザのセキュリティ機能を活用したい。なぜなら現状ヘッダーが未設定でブラウザ側の保護機能が活用されていないから。

## Acceptance Criteria

### AC-1: セキュリティヘッダーの付与

- [ ] WHILE APIサーバーがレスポンスを返す際
      THE SYSTEM SHALL 以下のセキュリティヘッダーを付与する: - `X-Content-Type-Options: nosniff` - `X-Frame-Options: DENY` - `X-XSS-Protection: 0` - `Referrer-Policy: strict-origin-when-cross-origin` - `Permissions-Policy: camera=(), microphone=(), geolocation=()`

### AC-2: 全エンドポイントへの適用

- [ ] WHEN 任意のAPIエンドポイントにリクエストを送信した際
      THEN レスポンスに上記セキュリティヘッダーが全て含まれている

### AC-3: CORS・既存ヘッダーとの共存

- [ ] WHEN CORSプリフライトリクエスト（OPTIONS）が送信された際
      THEN CORSヘッダーとセキュリティヘッダーが共に返される
      AND 既存のContent-Type等のヘッダーに影響しない

## 備考

- `X-XSS-Protection: 0` はモダンブラウザではXSSフィルタを無効化する推奨値（CSPで代替）
- `Strict-Transport-Security`（HSTS）はインフラ層での設定が推奨のため、今回はスコープ外
- `Content-Security-Policy`（CSP）はフロントエンド依存のため、EPIC-006と連携して別途検討
