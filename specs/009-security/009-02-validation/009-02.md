# Story: API入力バリデーション強化

## 親EPIC

[009: セキュリティ強化](../009-security.md)

## ユーザーストーリー

**ペルソナ**: システム運用者
**目的**: 全APIエンドポイントの入力バリデーションを強化する
**価値**: 過度に長い入力や不正なパターンの注入を防止し、システムの堅牢性を向上させる
**理由**: 現状のZodスキーマは型レベルの検証のみで、文字列長やパターン制限が不十分である

> システム運用者として、全APIエンドポイントの入力バリデーションを強化して、不正な入力パターンの注入を防止したい。なぜなら現状のバリデーションは型レベルのみで制約が不十分だから。

## Acceptance Criteria

### AC-1: 文字列長制限

- [x] WHEN 文字列フィールドに過度に長い入力が送信された際
      THEN システムは最大長バリデーションで拒否する
      AND RFC 7807形式で400 Bad Requestを返す

### AC-2: articleIdパターン制限

- [x] WHEN articleIdフィールドに不正な文字を含む入力が送信された際
      GIVEN 英数字・ハイフン・アンダースコア以外の文字が含まれる場合
      THEN システムはパターンバリデーションで拒否する

### AC-3: 既存テストの維持

- [x] WHEN バリデーション強化後に既存のAPIテストを実行した際
      THEN 全テストが引き続きパスする
