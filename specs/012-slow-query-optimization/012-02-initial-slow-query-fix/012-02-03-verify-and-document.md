# Subtask: 改善効果の検証・記録

## 親Story

[012-02: 初回スロークエリ対応](./012-02-initial-slow-query-fix.md)

## ユーザーストーリー

**ペルソナ**: 開発者（プロジェクトオーナー）
**目的**: マイグレーション適用後の効果を検証し、対応記録をドキュメントに残す
**価値**: 改善の効果が客観的に確認でき、今後の対応に活かせる知見が蓄積される
**理由**: 意思決定プロセスの学習蓄積がプロジェクト目標の一つであるため

> 開発者として、改善効果を検証し対応記録をドキュメントに残して、今後の対応に活かせる知見を蓄積したい。なぜなら意思決定プロセスの学習蓄積がプロジェクト目標の一つであるから。

## Acceptance Criteria

- [ ] WHEN マイグレーションが本番環境に適用された後
      GIVEN Supabaseダッシュボードでスロークエリの状態が確認できる場合
      THEN 改善対象クエリのアラートが解消されている、または実行時間が目標値以内に改善されている

- [ ] WHEN 効果検証が完了した際
      GIVEN 対応記録テンプレートが存在する場合
      THEN `docs/slow-query-optimization.md` の「対応記録」セクションに以下が追記されている: - 検出: pg_stat_statements での検出状況 - 分析: ボトルネックの特定内容 - Why: なぜこの改善方法を選択したか - How: マイグレーションファイル名 - 効果: 改善前後の実行時間

## 設計

### 対応記録のフォーマット（テンプレート準拠）

```markdown
### [日付] 対応 #1: [クエリ概要]

**検出**:

- クエリ: `SELECT ...`
- 平均実行時間: X ms
- 呼び出し回数: Y 回
- 影響エンドポイント: `POST /recommend`

**分析**:

- ボトルネック: [具体的なボトルネック]
- 既存インデックス: [関連するインデックスの有無]

**Why**:
[なぜこの改善方法を選択したかの記述]

**How**:

- マイグレーション: `supabase/migrations/YYYYMMDD000001_optimize_xxx.sql`
- 改善内容: [具体的な変更内容]

**効果**:

- 改善前: X ms (平均)
- 改善後: Y ms (平均)
- 改善率: Z%
```
