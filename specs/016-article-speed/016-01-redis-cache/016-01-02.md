# Subtask: wiki-proxy HTMLキャッシュ導入

## 親Story

[016-01: Redisキャッシュレイヤー導入](./016-01-redis-cache.md)

## ユーザーストーリー

**ペルソナ**: 推薦記事を閲覧するユーザー
**目的**: 記事のiframe表示を高速化する
**価値**: 同じ記事の2回目以降の表示が瞬時に行われる
**理由**: wiki-proxyは毎回scp-jp.wikidot.comにHTTPリクエスト+DOM解析を行っており、500-2000msのレイテンシが発生しているから

> ユーザーとして、記事のiframe表示を高速化して、同じ記事の2回目以降の表示が瞬時に行われるようにしたい。なぜなら毎回外部HTTPリクエスト+DOM解析が行われ500-2000msのレイテンシが発生しているから。

## Acceptance Criteria

### AC1: キャッシュキー設計

- [x] キャッシュキーは `wiki:html:{articleId}` 形式であること
- [x] articleIdは小文字正規化後の値を使用すること（既存の `rawPath.toLowerCase()` と一致）

### AC2: キャッシュ動作（HTMLレスポンス）

- [x] WHEN wiki-proxyにHTMLリクエストが到達した際
      GIVEN Redisにキャッシュが存在する場合
      THEN キャッシュからHTMLを返すこと
      AND 外部サイト（scp-jp.wikidot.com）へのHTTPリクエストを送信しないこと
      AND `Cache-Control: public, max-age=300, s-maxage=600` ヘッダーを維持すること
- [x] WHEN wiki-proxyにHTMLリクエストが到達した際
      GIVEN Redisにキャッシュが存在しない場合
      THEN 外部サイトからHTMLを取得し、processHtml()で処理すること
      AND 処理結果をRedisにTTL 3600秒（1時間）で保存すること
      AND レスポンスを返すこと

### AC3: 非HTMLリソース

- [x] WHEN 非HTMLリソース（CSS/JS/画像）のリクエストの場合
      THEN キャッシュ対象外とし、既存のパススルー動作を維持すること

### AC4: キャッシュ無効時

- [x] WHEN Redisが未設定（接続情報なし）の場合
      THEN 既存動作と完全に同一の振る舞いをすること（graceful degradation）

### AC5: テスト

- [x] wiki-proxyのキャッシュヒット時のテストが存在すること
- [x] wiki-proxyのキャッシュミス時のテストが存在すること
- [x] 非HTMLリソースがキャッシュされないことのテストが存在すること
- [x] Redis未設定時のフォールバックテストが存在すること
- [x] 既存のwiki-proxyテストがすべて通過すること
- [x] テストケース名は日本語で記述されていること

### 実装方針

```typescript
// wiki-proxy.ts の GET /* ハンドラ内
// HTMLレスポンスの場合のみキャッシュ
if (contentType.includes("text/html")) {
  // 1. キャッシュチェック
  const cacheKey = `wiki:html:${path}`;
  const cached = await cacheGet<string>(cacheKey);
  if (cached) {
    return new Response(cached, {
      status: 200,
      headers: {
        "content-type": contentType,
        "cache-control": "public, max-age=300, s-maxage=600",
      },
    });
  }

  // 2. キャッシュミス → 外部fetch + processHtml
  const html = await response.text();
  const processed = processHtml(html);

  // 3. キャッシュ保存（非同期、レスポンスをブロックしない）
  void cacheSet(cacheKey, processed, 3600);

  return new Response(processed, { ... });
}
```

### 技術的考慮事項

- processHtml()の結果（50-200KB）をキャッシュ。外部fetch + DOM解析を完全スキップ
- キャッシュ保存は `void` で非同期実行し、レスポンスをブロックしない
- TTL 1時間で自動eviction。Upstash Free tier 256MB制約内で運用可能
- キャッシュチェックはHTMLレスポンス判定の**前**に行う（外部fetchを回避するため）
