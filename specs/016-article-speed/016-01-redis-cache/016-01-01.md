# Subtask: Redisクライアント・キャッシュヘルパー実装

## 親Story

[016-01: Redisキャッシュレイヤー導入](./016-01-redis-cache.md)

## ユーザーストーリー

**ペルソナ**: APIサーバー開発者
**目的**: Upstash Redisへの接続とキャッシュ操作を統一的に行う基盤を構築する
**価値**: 各エンドポイントから一貫したキャッシュ操作が可能になる
**理由**: キャッシュの接続管理・エラーハンドリング・TTL設定を各所で重複実装したくないから

> APIサーバー開発者として、Redisへの接続とキャッシュ操作を統一的に行う基盤を構築して、各エンドポイントから一貫したキャッシュ操作を可能にしたい。なぜなら接続管理・エラーハンドリング・TTL設定を各所で重複実装したくないから。

## Acceptance Criteria

### AC1: パッケージ導入

- [ ] `@upstash/redis` が `apps/api-server` の dependencies に追加されていること

### AC2: 環境変数

- [ ] WHEN Upstash Redisの接続情報を設定する際
      THEN `UPSTASH_REDIS_REST_URL` と `UPSTASH_REDIS_REST_TOKEN` を以下に設定する
      AND `packages/shared/src/lib/env.ts` にオプショナルなゲッターを追加する
      AND ルートの `.env.example` にテンプレートを追加する
- [ ] WHERE CI環境（GitHub Actions）
      THE SYSTEM SHALL Redisクライアントを `vi.mock()` でモック化する（既存パターン準拠）
      AND GitHub Secretsへの追加は不要とする
- [ ] WHERE Vercel上のAPI Route
      THE SYSTEM SHALL Vercel Dashboard の Environment Variables に本番用の値を設定する（Production + Preview）

### AC3: Redisクライアント

- [ ] `apps/api-server/src/lib/redis.ts` にRedisクライアント初期化関数を実装すること
- [ ] WHEN `UPSTASH_REDIS_REST_URL` または `UPSTASH_REDIS_REST_TOKEN` が未設定の場合
      THEN `getRedisClient()` は `null` を返すこと（エラーにならない）
- [ ] WHEN 環境変数が正しく設定されている場合
      THEN `Redis` インスタンスを返すこと

### AC4: キャッシュヘルパー

- [ ] `apps/api-server/src/lib/cache.ts` にキャッシュヘルパーを実装すること
- [ ] `cacheGet<T>(key: string): Promise<T | null>` が実装されていること
- [ ] `cacheSet(key: string, value: unknown, ttlSeconds: number): Promise<void>` が実装されていること
- [ ] WHEN Redisクライアントが `null`（未設定）の場合
      THEN `cacheGet` は常に `null` を返し、`cacheSet` は何もしないこと（graceful degradation）
- [ ] WHEN Redisでエラーが発生した場合
      THEN エラーをログ出力し、`cacheGet` は `null` を返すこと（エラーを上位に伝播しない）

### AC5: テスト

- [ ] `redis.ts` の単体テストが存在すること（環境変数あり/なしの分岐）
- [ ] `cache.ts` の単体テストが存在すること（Redis有効/無効/エラー時の分岐）
- [ ] テストケース名は日本語で記述されていること


### インターフェース定義

```typescript
// redis.ts
import { Redis } from "@upstash/redis";

export const getRedisClient = (): Redis | null => {
  const url = process.env.UPSTASH_REDIS_REST_URL;
  const token = process.env.UPSTASH_REDIS_REST_TOKEN;
  if (!url || !token) return null;
  return new Redis({ url, token });
};

// cache.ts
export const cacheGet = async <T>(key: string): Promise<T | null> => { ... };
export const cacheSet = async (key: string, value: unknown, ttlSeconds: number): Promise<void> => { ... };
```

### 技術的考慮事項

- `process.env` 直接参照の例外: `env.ts` にオプショナルゲッターを追加するが、Redis接続情報は必須ではないためバリデーションエラーを投げない
- キャッシュヘルパーはシングルトンRedisクライアントを内部で保持
- テストでは `vi.mock("@upstash/redis")` でモック化（既存パターンに準拠）
