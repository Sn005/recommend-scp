# Subtask: articles/contentキャッシュ導入

## 親Story

[016-01: Redisキャッシュレイヤー導入](./016-01-redis-cache.md)

## ユーザーストーリー

**ペルソナ**: 推薦記事を閲覧するユーザー
**目的**: 記事のタイトル・本文冒頭・著者情報の取得を高速化する
**価値**: 推薦画面のカード情報表示や記事ページの著者表示が瞬時に行われる
**理由**: getContentは毎回scp-jp.wikidot.comにHTTPリクエスト+DOM解析を行っており、500-1500msのレイテンシが発生しているから

> ユーザーとして、記事のタイトル・本文冒頭・著者情報の取得を高速化して、推薦画面のカード情報や著者表示が瞬時に行われるようにしたい。なぜなら毎回外部HTTPリクエスト+DOM解析が行われ500-1500msのレイテンシが発生しているから。

## Acceptance Criteria

### AC1: キャッシュキー設計

- [x] キャッシュキーは `article:content:{articleId}` 形式であること
- [x] articleIdは小文字正規化後の値を使用すること（既存の `articleId.toLowerCase()` と一致）

### AC2: キャッシュ動作

- [x] WHEN articles/:articleId/content にリクエストが到達した際
      GIVEN Redisにキャッシュが存在する場合
      THEN キャッシュから `{ title, excerpt, author }` を返すこと
      AND 外部サイト（scp-jp.wikidot.com）へのHTTPリクエストを送信しないこと
      AND DBクエリ（getAuthorByArticleId）も実行しないこと
- [x] WHEN articles/:articleId/content にリクエストが到達した際
      GIVEN Redisにキャッシュが存在しない場合
      THEN 既存のロジック（外部fetch + DOM解析 + DB著者取得）を実行すること
      AND 結果をRedisにTTL 3600秒（1時間）で保存すること
      AND レスポンスを返すこと

### AC3: エラー時の動作

- [x] WHEN 外部fetch/DOM解析が失敗した場合
      THEN 既存のフォールバック動作（空レスポンス `{ title: "", excerpt: "", author: "" }`）を維持すること
      AND 失敗結果はキャッシュに保存しないこと

### AC4: キャッシュ無効時

- [x] WHEN Redisが未設定（接続情報なし）の場合
      THEN 既存動作と完全に同一の振る舞いをすること（graceful degradation）

### AC5: テスト

- [x] articles/contentのキャッシュヒット時のテストが存在すること
- [x] articles/contentのキャッシュミス時のテストが存在すること
- [x] 外部fetch失敗時にキャッシュ保存されないことのテストが存在すること
- [x] Redis未設定時のフォールバックテストが存在すること
- [x] 既存のarticlesテストがすべて通過すること
- [x] テストケース名は日本語で記述されていること

### 実装方針

```typescript
// service.ts の getContent メソッド内
getContent = async (articleId: string): Promise<ContentResult> => {
  const lowerArticleId = articleId.toLowerCase();
  const cacheKey = `article:content:${lowerArticleId}`;

  // 1. キャッシュチェック
  const cached = await cacheGet<ContentResult>(cacheKey);
  if (cached) return cached;

  // 2. キャッシュミス → 既存ロジック
  const url = `http://scp-jp.wikidot.com/${lowerArticleId}`;
  // ... 既存の外部fetch + DOM解析

  if (result.title || result.excerpt) {
    void cacheSet(cacheKey, result, 3600);
  }

  return result;
};
```

### 呼び出し元（影響範囲）

| 呼び出し元     | ファイル                                    | 用途                      |
| -------------- | ------------------------------------------- | ------------------------- |
| 推薦画面       | `apps/web/.../useArticleContent.ts`         | カードのtitle/excerpt表示 |
| 記事閲覧ページ | `apps/web/.../article/[articleId]/page.tsx` | 著者表示                  |

### 技術的考慮事項

- キャッシュ値は `{ title, excerpt, author }` の小さなJSON（~200B）
- Upstash Free tier への影響は極めて軽微
- 空レスポンス（title/excerptが空文字列）はキャッシュしない → 次回リクエストでリトライ可能
- キャッシュ保存は `void` で非同期実行し、レスポンスをブロックしない
