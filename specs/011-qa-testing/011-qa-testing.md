# EPIC-011: QAテスト基盤

## 概要

E2Eテストによる正常系品質担保の基盤を構築する。Playwright + CSV/TSV形式でテストケースを管理し、AIによるテストケース自動生成を実現する。

## ユーザーストーリー

**ペルソナ**: 開発者
**目的**: EPIC/Story完了時にAIがE2Eテストケースを自動生成し、CIで正常系の品質を担保する
**価値**: 手動テスト工数を削減しつつ、リグレッションを防止できる
**理由**: UIの変更に強く、Git差分が見やすいテスト管理を実現したい

## 背景・動機

- 現状、E2Eテストが未導入でリグレッション検知ができない
- テストケースの管理が属人化しやすい
- UI変更時にテストが壊れやすい（セレクタ依存）
- テストケース作成の工数が大きい

## スコープ

### 含む

- Playwright環境構築
- data-testid属性によるセレクタ戦略
- CSV/TSV形式でのテストケース管理
- AIによるテストケース自動生成
- GitHub Actions CI統合
- 全画面（オンボーディング、推薦、お気に入り）の正常系テスト

### 含まない（将来対応）

- 異常系・エッジケーステスト
- パフォーマンステスト
- ローカル実行環境の整備
- マルチブラウザ対応

## 技術決定事項

| 項目             | 決定                 | 理由                                 |
| ---------------- | -------------------- | ------------------------------------ |
| フレームワーク   | Playwright           | マルチブラウザ対応、高速、MS製で安定 |
| セレクタ戦略     | data-testid          | UI変更に強い                         |
| テストケース形式 | CSV                  | Git差分が見やすい、AIパース容易      |
| 実行環境         | CIのみ               | 運用シンプル化                       |
| ブラウザ         | Chromiumのみ         | MVP段階                              |
| 失敗時           | 正常系のみブロッカー | tags=criticalで制御                  |

## 受け入れ条件（EPICレベル）

- [ ] `pnpm test:e2e` でE2Eテストが実行できる
- [ ] テストケースがCSV形式で管理されている
- [ ] AIがEPIC/Story仕様からテストケースを生成できる
- [ ] CIで正常系テスト失敗時にマージがブロックされる
- [ ] 全画面（オンボーディング、推薦、お気に入り）の正常系がテストされている
