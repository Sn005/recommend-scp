# EPIC: 運用・監視

## ユーザーストーリー

**ペルソナ**: 開発者・運用者
**目的**: 致命的エラー発生時にGitHub Issueで通知を受け取り原因調査ができる状態にする
**価値**: サービスの安定運用を最低限のコストで実現できる
**理由**: 外部SaaSなし・無料枠内でサービスの安定運用を実現したい

> 開発者・運用者として、致命的エラー（パイプライン失敗・サービスダウン）の発生時にGitHub Issueで自動通知を受け取り、迅速に原因調査に着手したい。なぜなら外部SaaSなし・無料枠内でサービスの安定運用を実現したいから。

## Acceptance Criteria

- [ ] パイプライン失敗時にGitHub Issueが自動作成され、エラー情報が含まれること
- [ ] ヘルスチェックが1時間おきに実行され、障害時にGitHub Issueで通知されること
- [ ] 同一原因の重複Issueが防止されること
- [ ] トラブルシューティングRunbookが整備されていること

## 設計制約

- 外部SaaS不使用（GitHub Actions + 既存基盤のみ）
- Vercel無料プラン範囲内
- GitHub Actions無料枠（2,000分/月）の範囲内
- 既存のpino構造化ログ・エラーハンドラー・ヘルスチェックをそのまま活用

## トレードオフ決定事項

| 観点           | 決定                           | 理由                                    |
| -------------- | ------------------------------ | --------------------------------------- |
| エラー監視     | 既存pino + エラーハンドラー    | Sentryは現フェーズではオーバースペック  |
| ダッシュボード | なし                           | 小規模サービスには過剰                  |
| 外形監視       | GitHub Actions cron            | 完全無料で十分                          |
| ログ永続化     | stdout（Vercelログビューア）   | Vercel無料プランの範囲で十分            |
| Issue起票      | GitHub Actions + github-script | シンプル・GITHUB_TOKEN自動提供          |
| 監視頻度       | 1時間おき                      | 個人プロジェクトに十分（月約720分消費） |
| 通知先         | GitHub Issues + メール         | 無料範囲内で最適                        |
