# Subtask 006-01-04: visitorId管理フック

## 概要

クライアント側でvisitorIdを管理するカスタムフック（useVisitorId）を実装する。
localStorage連携とAPI呼び出しを統一したインターフェースで提供。

- **status**: planned

## ユーザーストーリー

**ペルソナ**: フロントエンド開発者
**目的**: visitorIdの取得・生成・API登録を統一したフックで呼び出せる
**価値**: コンポーネント間でvisitorId管理ロジックを共有できる
**理由**: 重複コードを排除し、一貫したユーザー識別を実現したい

> フロントエンド開発者として、visitorIdの取得・生成・API登録を統一したフックで呼び出せるようにしたい。なぜなら重複コードを排除し、一貫したユーザー識別を実現したいから。

## Acceptance Criteria（EARS記法）

### AC-1: visitorId初期化

- [ ] WHEN useVisitorIdフックが呼び出された際
      GIVEN localStorageにvisitorIdが存在しない場合
      THEN 新規UUIDを生成する
      AND localStorageに保存する
      AND POST /visitors APIを呼び出す

### AC-2: visitorId取得（既存）

- [ ] WHEN useVisitorIdフックが呼び出された際
      GIVEN localStorageにvisitorIdが存在する場合
      THEN 既存のvisitorIdを返す
      AND APIは呼び出さない

### AC-3: ローディング状態

- [ ] WHEN visitorIdを初期化中の際
      THEN isLoadingがtrueになる
      AND 初期化完了後にfalseになる

### AC-4: エラーハンドリング

- [ ] WHEN POST /visitors APIがエラーを返した際
      THEN errorオブジェクトに詳細を格納する
      AND visitorIdはnullのまま

### AC-5: オンボーディング状態確認

- [ ] WHEN useVisitorIdフックが呼び出された際
      GIVEN visitorIdが登録済みかつonboarding完了済みの場合
      THEN isOnboardedがtrueになる

### AC-6: Server State Sync

- [ ] WHEN visitorIdが存在するが初回マウント時
      THEN サーバー側の状態（onboardingCompletedAt）を取得する
      AND ローカル状態と同期する

## 技術設計

### インターフェース定義

```typescript
interface UseVisitorIdResult {
  /** 現在のvisitorId（未初期化時はnull） */
  visitorId: string | null;
  /** 初期化中またはAPI呼び出し中 */
  isLoading: boolean;
  /** オンボーディング完了済みかどうか */
  isOnboarded: boolean;
  /** エラー情報 */
  error: Error | null;
  /** visitorIdをリフレッシュ（デバッグ用） */
  refresh: () => Promise<void>;
}

function useVisitorId(): UseVisitorIdResult;
```

### localStorageキー

```typescript
const VISITOR_ID_KEY = "recommend_scp_visitor_id";
const ONBOARDING_COMPLETED_KEY = "recommend_scp_onboarding_completed";
```

### 実装方針

```typescript
// apps/web/src/shared/hooks/useVisitorId.ts

import { useEffect, useState, useCallback } from "react";
import { hc } from "hono/client";
import type { AppType } from "@recommend-scp/api-types";

const VISITOR_ID_KEY = "recommend_scp_visitor_id";

export function useVisitorId(): UseVisitorIdResult {
  const [visitorId, setVisitorId] = useState<string | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [isOnboarded, setIsOnboarded] = useState(false);
  const [error, setError] = useState<Error | null>(null);

  const initialize = useCallback(async () => {
    setIsLoading(true);
    setError(null);

    try {
      // 1. localStorageから取得
      const stored = localStorage.getItem(VISITOR_ID_KEY);

      if (stored) {
        setVisitorId(stored);
        // サーバー側の状態を確認（onboarding完了状態）
        // 今回はPOST /visitorsのレスポンスで確認
        // 既存visitorの場合はサーバー側でonboardingCompletedAtを返す
      } else {
        // 2. 新規UUID生成
        const newId = crypto.randomUUID();
        localStorage.setItem(VISITOR_ID_KEY, newId);

        // 3. APIに登録
        const api = hc<AppType>(process.env.NEXT_PUBLIC_API_URL!);
        const res = await api.visitors.$post({
          json: { visitorId: newId },
        });

        if (!res.ok) {
          throw new Error("Failed to register visitor");
        }

        setVisitorId(newId);
      }
    } catch (e) {
      setError(e instanceof Error ? e : new Error("Unknown error"));
    } finally {
      setIsLoading(false);
    }
  }, []);

  useEffect(() => {
    initialize();
  }, [initialize]);

  return {
    visitorId,
    isLoading,
    isOnboarded,
    error,
    refresh: initialize,
  };
}
```

- [ ] localStorageにvisitorIdが存在する場合、それを返す
- [ ] 既存visitorの場合、APIは呼び出されない

- [ ] 初期化完了後はisLoadingがfalseになる
- [ ] APIエラー時にerrorが設定される
- [ ] オンボーディング完了済みの場合、isOnboardedがtrueになる
- [ ] refresh関数で再初期化できる
