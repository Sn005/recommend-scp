# Story: 記事閲覧

## 親EPIC

[006: フロントエンドUI](../006-frontend.md)

## ユーザーストーリー

**ペルソナ**: SCPファン
**目的**: 推薦された記事を没入感のある全画面で読む
**価値**: 気に入った記事を保存し、興味のない記事はスキップできる
**理由**: 手軽にSCP記事を楽しみたい

> SCPファンとして、推薦された記事を没入感のある全画面で読み、気に入った記事を保存したい。なぜなら手軽にSCP記事を楽しみたいから。

## 背景

### コア体験

- **没入型閲覧**: 全画面WebViewで元サイトの記事をそのまま表示
- **シームレス遷移**: 記事最下部で次の記事が自動読み込み（無限スクロール）
- **ミニマル操作**: ボタンは最小限（お気に入り、次へ）

### UIレイアウト

```
┌─────────────────────────────────────┐
│ SCP-173                    [次へ →]│ ← 自動非表示ヘッダー
├─────────────────────────────────────┤  （スクロールで隠れる）
│                                     │
│                                     │
│        [全画面 WebView]             │
│        （元サイトの記事）           │
│                                     │
│        （スクロール中...）          │
│                                     │
│        ─── シームレス ───           │
│                                     │
│        [次の記事]                   │
│        ↑ 自動読み込み               │
│                                     │
└───────────────────────────────[♡]──┘
                              ↑ お気に入り
```

### フィードバック判定ロジック

| アクション             | フィードバック種別 | 重み |
| ---------------------- | ------------------ | ---- |
| 記事最下部到達（読了） | 暗黙的Like         | 中   |
| 「次へ」ボタン押下     | Dislike            | 中   |
| お気に入りボタン押下   | 明示的Like         | 高   |

## Acceptance Criteria

### AC-1: 記事閲覧画面表示

- [ ] WHEN ユーザーがオンボーディング完了後に遷移した際
      THEN 記事閲覧画面が表示される
      AND POST /recommend APIから推薦記事を取得する
      AND 最初の記事がWebViewで表示される

### AC-2: 全画面WebView

- [ ] WHEN 記事が表示された際
      THEN 画面全体にWebView（iframe）が表示される
      AND 元サイトの記事コンテンツがそのまま表示される
      AND 記事内のスクロール・リンク押下が自由にできる

### AC-3: 自動非表示ヘッダー

- [ ] WHEN ユーザーが下方向にスクロールした際
      THEN ヘッダーがアニメーション付きで非表示になる
- [ ] WHEN ユーザーが上方向にスクロールした際
      THEN ヘッダーがアニメーション付きで再表示される

### AC-4: ヘッダータイトル自動更新

- [ ] WHEN ユーザーが次の記事までスクロールした際
      THEN ヘッダーのタイトルが新しい記事のSCP番号に更新される
      AND Intersection Observer APIで検知される

### AC-5: 無限スクロール（次記事読み込み）

- [ ] WHEN ユーザーが現在の記事の最下部に到達した際
      THEN 次の推薦記事が自動的に読み込まれる
      AND 記事間にシームレスに接続される
      AND ローディングインジケータが一時的に表示される

### AC-6: 読了判定（暗黙的Like）

- [ ] WHEN ユーザーが記事最下部に到達した際
      THEN POST /feedback APIで暗黙的Likeが記録される
      AND 同じ記事は再度記録されない（重複防止）

### AC-7: スキップ（Dislike）

- [ ] WHEN ユーザーが「次へ」ボタンをタップした際
      THEN POST /feedback APIでDislikeが記録される
      AND 次の推薦記事が表示される
      AND スクロール位置が先頭にリセットされる

### AC-8: お気に入り追加

- [ ] WHEN ユーザーがお気に入りボタンをタップした際
      GIVEN 記事がお気に入りに未追加の場合
      THEN POST /feedback APIで明示的Likeが記録される
      AND ボタンの状態が「追加済み」に変化する

### AC-9: お気に入り解除

- [ ] WHEN ユーザーがお気に入りボタンをタップした際
      GIVEN 記事が既にお気に入りの場合
      THEN お気に入りが解除される
      AND ボタンの状態が「未追加」に変化する

### AC-10: 推薦切れ対応

- [ ] WHEN POST /recommend APIが空の結果を返した際
      THEN 「すべての推薦を読みました」メッセージが表示される
      AND 再オンボーディングを提案するボタンが表示される

### AC-11: エラーハンドリング

- [ ] WHEN 記事読み込み中にエラーが発生した際
      THEN シンプルなエラーメッセージが表示される
      AND リトライボタンが表示される

### スクロール位置検知（Intersection Observer）

```typescript
// 各記事の境界を検知してタイトルを更新
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        const articleId = entry.target.dataset.articleId;
        setCurrentArticle(articleId);
      }
    });
  },
  { threshold: 0.5 }
);
```

### API連携

```typescript
// 推薦取得
const articles = await api.recommend.$post({
  json: { visitorId, count: 5 },
});

// フィードバック記録
await api.feedback.$post({
  json: {
    visitorId,
    articleId,
    type: "like" | "dislike" | "favorite",
  },
});
```
