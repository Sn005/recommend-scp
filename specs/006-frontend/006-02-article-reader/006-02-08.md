# Subtask 006-02-08: お気に入りボタンAPI連携

## 親 Story

[006-02: 記事閲覧](./006-02.md)

## 概要

推薦画面のお気に入りボタン（useArticleFavorite フック）を favorites API に接続する。
現在はローカルキャッシュのみで動作しており、DBへの永続化と推薦エンジンへのシグナル伝達が
行われていない。POST /favorites（追加）と DELETE /favorites（解除）のAPI呼び出しを実装する。

## ステータス

- **status**: pending

## ユーザーストーリー

**ペルソナ**: SCPファン
**目的**: お気に入りボタンの操作をサーバーに永続化する
**価値**: ページリロード後もお気に入り状態が維持され、推薦精度が向上する
**理由**: お気に入りした記事が消えず、好みに合った推薦を継続的に受けたい

> SCPファンとして、お気に入りボタンの操作をサーバーに永続化して、リロード後も状態が維持され推薦精度が向上するようにしたい。なぜなら好みに合った推薦を継続的に受けたいから。

## Acceptance Criteria（EARS記法）

### お気に入り追加

- [ ] AC-1: お気に入り追加時に POST API を呼び出す
  - WHEN ユーザーがお気に入りボタンをタップした際
  - GIVEN 記事がお気に入りに未追加の場合
  - THEN POST /favorites/:articleId API を呼び出す
  - AND 楽観的更新で即座にUIを反映する（既存動作を維持）

- [ ] AC-2: 追加API失敗時にロールバックする
  - WHEN POST /favorites/:articleId が失敗した際
  - THEN お気に入り状態を元に戻す（♥ → ♡）
  - AND ローカルキャッシュもロールバックする

### お気に入り解除

- [ ] AC-3: お気に入り解除時に DELETE API を呼び出す
  - WHEN ユーザーがお気に入りボタンをタップした際
  - GIVEN 記事が既にお気に入りの場合
  - THEN DELETE /favorites/:articleId API を呼び出す
  - AND 楽観的更新で即座にUIを反映する（既存動作を維持）

- [ ] AC-4: 解除API失敗時にロールバックする
  - WHEN DELETE /favorites/:articleId が失敗した際
  - THEN お気に入り状態を元に戻す（♡ → ♥）
  - AND ローカルキャッシュもロールバックする

### visitorId 連携

- [ ] AC-5: API呼び出し時に visitorId を送信する
  - WHEN お気に入りの追加/解除 API を呼び出す際
  - THEN リクエストボディに useVisitorId から取得した visitorId を含める
  - AND visitorId が未取得の場合はAPIコールをスキップする（ローカルキャッシュのみ更新）

### 既存動作の維持

- [ ] AC-6: 連打防止・Optimistic UI を維持する
  - WHILE API呼び出しが進行中の間
  - THE SYSTEM SHALL 追加のタップを無視する（既存の isProcessingRef 動作を維持）

- [ ] AC-7: useFeedback の recordFavorite 呼び出しを除去する
  - WHEN お気に入り追加が実行された際
  - THEN favorites API のみを呼び出す
  - AND useFeedback.recordFavorite は呼び出さない（favorites テーブルと feedback テーブルの二重管理を防止）

### useArticleFavorite.ts の変更概要

```typescript
// 1. api クライアントのインポートを有効化
import { api } from "@/shared/lib/api-client";
import { useVisitorId } from "@/shared/hooks/useVisitorId";

// 2. visitorId を取得
const { visitorId } = useVisitorId();

// 3. addFavorite: POST API 呼び出しを追加
const addFavorite = useCallback(async () => {
  // ... 既存の楽観的更新ロジック ...
  try {
    if (visitorId) {
      await api.favorites[":articleId"].$post({
        param: { articleId },
        json: { visitorId },
      });
    }
  } catch {
    // ロールバック
  }
}, [articleId, isFavorited, visitorId]);

// 4. removeFavorite: DELETE API 呼び出しを有効化
const removeFavorite = useCallback(async () => {
  // ... 既存の楽観的更新ロジック ...
  try {
    if (visitorId) {
      await api.favorites[":articleId"].$delete({
        param: { articleId },
        json: { visitorId },
      });
    }
  } catch {
    // ロールバック
  }
}, [articleId, isFavorited, visitorId]);
```

### page.tsx の変更概要

```typescript
// handleFavorite から recordFavorite の呼び出しを除去
// （favorites テーブルに直接永続化するため、feedback 経由は不要）
const handleFavorite = useCallback(() => {
  if (currentArticle) {
    void recordLike(currentArticle.id); // like フィードバックは維持
  }
  void toggleFavorite(); // favorites API 経由で永続化
}, [currentArticle, recordLike, toggleFavorite]);
```

**注**: `recordLike` は推薦エンジンの like シグナル（重み1.0）として別途機能するため維持する。
favorites API による重み2.0 シグナルとは独立した役割。
