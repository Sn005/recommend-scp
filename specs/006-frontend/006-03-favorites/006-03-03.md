# Subtask: API連携フック

## 親Story

[006-03: お気に入り管理](./006-03.md)

## ユーザーストーリー

**ペルソナ**: 開発者
**目的**: お気に入りAPIとの通信を抽象化し、UIコンポーネントから利用可能にする
**価値**: API通信の複雑さを隠蔽し、状態管理を一元化できる
**理由**: コンポーネントがAPI詳細を意識せずにデータを取得・更新したい

> 開発者として、お気に入りAPIとの通信を抽象化したフックを提供したい。なぜならUIコンポーネントがAPI詳細を意識せずにデータを扱えるようにしたいから。

## 背景

### 責務

- GET /favorites APIからお気に入り一覧を取得
- DELETE /favorites/:id APIでお気に入りを削除
- ローディング・エラー状態の管理
- API未実装時のモック対応

### 参考実装

- `apps/web/src/app/(main)/recommend/_hooks/useFeedback.ts`
- `apps/web/src/shared/hooks/useVisitorId.ts`

## Acceptance Criteria

### AC-1: 一覧取得

- [ ] WHEN `useFavorites` hookが呼び出された際
      GIVEN visitorIdが存在する場合
      THEN GET /favorites APIを呼び出す
      AND `favorites` 配列にお気に入り一覧がセットされる

### AC-2: ローディング状態

- [ ] WHEN API呼び出し中の場合
      THEN `isLoading` がtrueになる
      AND API完了後にfalseになる

### AC-3: エラー状態

- [ ] WHEN API呼び出しが失敗した場合
      THEN `error` にErrorオブジェクトがセットされる
      AND `favorites` は空配列のまま維持される

### AC-4: お気に入り削除

- [ ] WHEN `removeFavorite(articleId)` が呼び出された際
      GIVEN 有効なarticleIdが渡された場合
      THEN DELETE /favorites/:id APIを呼び出す
      AND 失敗時はエラー処理を行う（楽観的更新をロールバック）

### AC-5: 削除の楽観的更新

- [ ] WHEN `removeFavorite` が呼び出された際
      THEN 即座にUI上から該当記事を削除する（楽観的更新）
      AND API失敗時は元の状態にロールバックする

### AC-6: リフレッシュ機能

- [ ] WHEN `refresh()` が呼び出された際
      THEN 一覧を再取得する
      AND エラー状態がクリアされる

### AC-7: モック対応

- [ ] WHEN `NEXT_PUBLIC_USE_MOCK_API=true` の場合
      THEN モックデータを返す
      AND 削除操作もモック上で動作する

## 技術設計

### インターフェース定義

```typescript
// _hooks/useFavorites.ts

interface FavoriteArticle {
  id: string; // お気に入りレコードID
  articleId: string; // 記事ID
  scpNumber: string; // "scp-173"
  title: string; // "彫刻 - オリジナル"
  excerpt: string; // 概要（100文字程度）
  objectClass: "safe" | "euclid" | "keter" | "thaumiel" | "neutralized" | "pending";
  rating: number; // +4102
  favoritedAt: string; // ISO8601形式
}

interface UseFavoritesResult {
  favorites: FavoriteArticle[];
  isLoading: boolean;
  error: Error | null;
  removeFavorite: (articleId: string) => Promise<void>;
  refresh: () => Promise<void>;
}

export function useFavorites(): UseFavoritesResult;
```

### 実装パターン

```typescript
export function useFavorites(): UseFavoritesResult {
  const { visitorId } = useVisitorId();
  const [favorites, setFavorites] = useState<FavoriteArticle[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  const fetchFavorites = useCallback(async () => {
    if (!visitorId) return;
    setIsLoading(true);
    setError(null);
    try {
      const res = await api.favorites.$get({ query: { visitorId } });
      if (!res.ok) throw new Error("Failed to fetch favorites");
      const data = await res.json();
      setFavorites(data.favorites);
    } catch (e) {
      setError(e instanceof Error ? e : new Error("Unknown error"));
    } finally {
      setIsLoading(false);
    }
  }, [visitorId]);

  const removeFavorite = useCallback(
    async (articleId: string) => {
      // 楽観的更新
      const prevFavorites = favorites;
      setFavorites((prev) => prev.filter((f) => f.articleId !== articleId));

      try {
        const res = await api.favorites[":id"].$delete({
          param: { id: articleId },
          json: { visitorId },
        });
        if (!res.ok) throw new Error("Failed to remove favorite");
      } catch {
        // ロールバック
        setFavorites(prevFavorites);
      }
    },
    [favorites, visitorId]
  );

  useEffect(() => {
    void fetchFavorites();
  }, [fetchFavorites]);

  return { favorites, isLoading, error, removeFavorite, refresh: fetchFavorites };
}
```

## テストケース

### 正常系

- [ ] visitorId存在時にGET APIが呼ばれること
- [ ] 取得したデータがfavorites配列にセットされること
- [ ] removeFavorite呼び出しでDELETE APIが呼ばれること
- [ ] 削除成功後に一覧が再取得されること
- [ ] refresh呼び出しで一覧が再取得されること

### 異常系

- [ ] API失敗時にerrorがセットされること
- [ ] 削除失敗時にロールバックされること
- [ ] visitorIdがない場合はAPIを呼ばないこと

### 状態管理

- [ ] API呼び出し中はisLoading=trueになること
- [ ] 楽観的更新で即座にUIが更新されること
