# Subtask 006-05-04: Cascade Prefetch（3スロットiframeプール）

## 概要

現在のデュアルiframe（Current + Next）を3スロットiframeプール（Current + Next + Prefetch）に拡張する。
「次へ」ボタン押下時の記事読み込み待ちを解消し、初回ロード速度を保護しつつ先読みを実現する。

## ステータス

- **status**: completed

## 親Story

[006-05: 記事遷移UX改善](./006-05.md)

## ユーザーストーリー

**ペルソナ**: SCPファン
**目的**: 「次へ」ボタンを押した時に待ち時間なく次の記事が表示される
**価値**: 読書体験が途切れない
**理由**: 記事読み込みの待ち時間はストレス

> SCPファンとして、「次へ」ボタンを押した時に待ち時間なく次の記事が表示されてほしい。なぜなら読書体験の途切れがストレスだから。

## 背景

### 現行のiframe構成

```
[Current iframe] ← 表示中
[Next iframe]    ← 非表示、プリレンダリング中
```

- page.tsxでデュアルWebViewとして実装済み
- 遷移時にスライドアニメーション（500ms）
- 遷移完了後に前の記事を破棄、新しいNextをプリレンダリング

### 課題

| 問題                                    | 影響                                                    |
| --------------------------------------- | ------------------------------------------------------- |
| Nextのiframeがまだ読み込み中の場合      | 「次へ」タップ時に白画面が一瞬見える                    |
| Prefetch（n+2）がない                   | Nextが表示に昇格した後、新しいNextの読み込みが0から開始 |
| 初回ロードでNext/Prefetchも同時読み込み | 最初の記事の表示速度が低下する可能性                    |

### Cascade Prefetch戦略

```
初回ロード:
  [Slot 0: Current] ← iframe作成、読み込み開始
  [Slot 1: Next]    ← Slot 0の読み込み完了後に作成・読み込み開始
  [Slot 2: Prefetch]← Slot 1の読み込み完了後に作成・読み込み開始

遷移時:
  [Slot 0: Current] → 破棄（iframe.src = ""、DOM削除）
  [Slot 1: Next]    → 新Slot 0（表示に昇格）
  [Slot 2: Prefetch]→ 新Slot 1（Next昇格）
  新Slot 2           → 新規作成、読み込み開始
```

## Acceptance Criteria（EARS記法）

### AC-1: 3スロットiframeプール

- [x] WHEN 記事閲覧画面が表示された際
      THEN 最大3つのiframeスロットが管理される
      AND Current（表示中）、Next（読み込み完了・非表示）、Prefetch（読み込み中・非表示）の3段階で管理される

### AC-2: 初回ロードの段階的読み込み

- [x] WHEN 記事閲覧画面が初回表示された際
      THEN 最初の記事（Current）のiframeのみが読み込まれる
      AND Currentの読み込み完了後にNext（n+1）のiframeが作成・読み込み開始される
      AND Nextの読み込み完了後にPrefetch（n+2）のiframeが作成・読み込み開始される

### AC-3: 遷移時のスロットローテーション

- [x] WHEN ユーザーが「次へ」ボタンをタップして遷移が完了した際
      THEN Currentスロットのiframeが破棄される
      AND NextスロットがCurrentに昇格する
      AND PrefetchスロットがNextに昇格する
      AND 新しいPrefetchスロットが作成され、n+2の記事の読み込みが開始される

### AC-4: iframe読み込み完了状態の追跡

- [x] WHERE iframeプール管理において
      THE SYSTEM SHALL 各スロットの読み込み完了状態（isLoaded）を追跡する
      AND iframeのloadイベントで完了を検知する

### AC-5: メモリ管理

- [x] WHEN スロットローテーションが実行された際
      THEN 破棄されるiframeのsrcが空文字列に設定される
      AND DOMから削除される
      AND 常に最大3つのiframeのみがDOMに存在する

### AC-6: 記事不足時のフォールバック

- [x] WHEN 先読み対象の記事がない場合（バッファ枯渇）
      THEN Prefetchスロットは作成されない
      AND NextまたはCurrentのスロットのみで動作する

### AC-7: 読み込み完了通知

- [x] WHEN Nextスロットのiframeが読み込み完了した際
      THEN TransitionCardの適応型タイミングに`isContentReady=true`を通知する

## 技術設計

### 新規Hook: useIframePool

```
app/(main)/recommend/_hooks/
└── useIframePool.ts
```

### インターフェース定義

```typescript
interface IframeSlot {
  /** 記事のインデックス（articles配列内） */
  articleIndex: number;
  /** 記事URL */
  url: string;
  /** iframe読み込み完了フラグ */
  isLoaded: boolean;
}

interface UseIframePoolOptions {
  /** 記事一覧 */
  articles: Article[];
  /** 現在表示中の記事インデックス */
  currentIndex: number;
}

interface UseIframePoolReturn {
  /** 現在のスロット状態 [Current, Next?, Prefetch?] */
  slots: [IframeSlot, IframeSlot | null, IframeSlot | null];
  /** Nextスロットの読み込み完了状態 */
  isNextReady: boolean;
  /** 次へ進む（スロットローテーション） */
  advance: () => void;
  /** iframeのloadイベントハンドラ */
  handleIframeLoad: (articleIndex: number) => void;
}
```

### Cascade読み込みロジック

```typescript
// Currentの読み込み完了を監視
useEffect(() => {
  if (slots[0].isLoaded && slots[1] === null && hasNextArticle) {
    // Next スロット作成
    createSlot(1, currentIndex + 1);
  }
}, [slots[0].isLoaded]);

useEffect(() => {
  if (slots[1]?.isLoaded && slots[2] === null && hasPrefetchArticle) {
    // Prefetch スロット作成
    createSlot(2, currentIndex + 2);
  }
}, [slots[1]?.isLoaded]);
```

### スロットローテーション

```typescript
const advance = useCallback(() => {
  setSlots(([current, next, prefetch]) => {
    // Current破棄、Next→Current、Prefetch→Next
    // 新Prefetchは次のuseEffectで作成
    return [
      next ?? createNewSlot(currentIndex + 1),
      prefetch,
      null, // 次のuseEffectで作成される
    ];
  });
}, [currentIndex]);
```

### page.tsx での使用

```tsx
// page.tsx
const { slots, isNextReady, advance, handleIframeLoad } = useIframePool({
  articles,
  currentIndex,
});

return (
  <div className="relative h-screen">
    {/* Current */}
    <ArticleWebView
      key={slots[0].articleIndex}
      url={slots[0].url}
      onLoad={() => handleIframeLoad(slots[0].articleIndex)}
      className={isTransitioning ? "opacity-0" : "opacity-100"}
    />

    {/* Next (hidden) */}
    {slots[1] && (
      <ArticleWebView
        key={slots[1].articleIndex}
        url={slots[1].url}
        onLoad={() => handleIframeLoad(slots[1].articleIndex)}
        className="absolute inset-0 opacity-0 pointer-events-none"
      />
    )}

    {/* Prefetch (hidden) */}
    {slots[2] && (
      <ArticleWebView
        key={slots[2].articleIndex}
        url={slots[2].url}
        onLoad={() => handleIframeLoad(slots[2].articleIndex)}
        className="absolute inset-0 opacity-0 pointer-events-none"
      />
    )}
  </div>
);
```

## テストケース

### useIframePool ユニットテスト

- [x] 初期状態でCurrentスロットのみが作成される
- [x] Current読み込み完了後にNextスロットが作成される
- [x] Next読み込み完了後にPrefetchスロットが作成される
- [x] advance()でCurrentが破棄されNextがCurrentに昇格する
- [x] advance()でPrefetchがNextに昇格する
- [x] advance()後に新しいPrefetchスロットが作成される
- [x] handleIframeLoad()で対象スロットのisLoadedがtrueになる
- [x] isNextReadyがNextスロットの読み込み完了を反映する
- [x] 記事が1つしかない場合、Next/Prefetchスロットが作成されない
- [x] 記事が2つの場合、Prefetchスロットが作成されない
- [x] advance()時にCurrentのiframeが破棄される（src=""）

### 結合テスト（page.tsx）

- [ ] 初回表示で最初の記事のiframeのみが表示される
- [ ] 2つ目のiframeが非表示で読み込まれる
- [ ] 「次へ」後にDOMのiframeが最大3つである
- [ ] 遷移後に前の記事のiframeがDOMから削除されている
