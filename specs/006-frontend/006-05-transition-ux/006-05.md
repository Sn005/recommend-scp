# Story: 記事遷移UX改善

## 親EPIC

[006: フロントエンドUI](../006-frontend.md)

## ユーザーストーリー

**ペルソナ**: SCPファン
**目的**: 記事間の遷移時にワクワク感を得ながら、待ち時間なく次の記事を読み始める
**価値**: 次に表示されるSCPのオブジェクトクラスと評価が一瞬見えることで期待感が高まり、読書体験が途切れない
**理由**: 記事を次々と読む中で、無機質な切り替えではなく「次は何が来るか」の楽しみが欲しい

> SCPファンとして、記事間の遷移時に次のSCPのオブジェクトクラスと評価が一瞬表示される遷移ヘッダーカードを見たい。なぜなら「次はKeterか！」というワクワク感を得ながら、待ち時間なく読書を続けたいから。

## 背景

### 設計の経緯

WikiTok方式（フルスワイプUI）の採用を検討したが、SCP記事は長文でスクロール必須のため不適合と判断。代替案として**遷移アニメーション内にヘッダーカードを差し込む**方式を採用した。

### 主要な設計決定

| 項目           | 決定事項                                    | 理由                                                                          |
| -------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| 遷移演出       | フェード + ヘッダーカード（0.5〜1s）        | 記事読み込み待ちを演出でマスク                                                |
| iframe構成     | 3スロットプール（Cascade Prefetch）         | 初回ロード速度保護 + 先読みで待ち時間解消                                     |
| プログレスバー | 削除                                        | 無限に記事が読み込まれるため進捗の概念が不要                                  |
| フィードバック | 暗黙的（scroll depth + dwell time）         | 明示的Dislikeボタンを廃止し、ユーザー負荷を軽減                               |
| 画像サムネイル | 不採用                                      | SCP Wikiが外部アクセスで503を返すため技術的に困難                             |
| カード情報     | SCP番号 + オブジェクトクラスバッジ + rating | subtitle/publishedYearはDB未対応のため将来課題（docs/\_archived/note.md参照） |

```
│    │   ▓▓▓ グラデーション背景 ▓▓▓   │    │
│    │                           │    │
│    │      SCP-173              │    │  ← SCP番号（白、大文字）

│    │                           │    │
│    └───────────────────────────┘    │
│                                     │
│      ┌─────────────────┐            │
│      │    ♡       →    │            │  ← PillNav（変更なし）
│      └─────────────────┘            │
└─────────────────────────────────────┘
```

### Cascade Prefetch（3スロットiframeプール）

```
[Slot 0: Current] ← 表示中（ユーザーが読んでいる記事）
[Slot 1: Next]    ← hidden, loaded（次の記事、読み込み完了済み）
[Slot 2: Prefetch]← hidden, loading（その次の記事、バックグラウンド読込中）

遷移時:
  Slot 0 → 破棄
  Slot 1 → 新Slot 0（表示）
  Slot 2 → 新Slot 1（hidden, loaded）
  新Slot 2 → 新規作成（次の先読み開始）
```

## Acceptance Criteria

### AC-1: 推薦APIレスポンスにobjectClassとratingが含まれる

- [ ] WHEN POST /recommend APIが推薦記事を返した際
      THEN 各記事にobjectClassフィールドが含まれる（SAFE/EUCLID/KETER/THAUMIEL/NEUTRALIZED/APOLLYON/ARCHON/null）
      AND 各記事にratingフィールドが含まれる（整数値/null）

### AC-2: 遷移ヘッダーカード表示

- [ ] WHEN ユーザーが「次へ」ボタンをタップした際
      THEN 次の記事のSCP番号、オブジェクトクラスバッジ、ratingが表示される遷移ヘッダーカードがフェードインする
      AND オブジェクトクラスに応じたグラデーション背景が適用される
      AND 0.5〜1.0秒の適応型タイミングで表示後、次の記事にフェードアウトする

### AC-3: Cascade Prefetch

- [ ] WHEN 記事が表示されている間
      THEN 次の記事（n+1）のiframeが非表示で読み込み完了済みである
      AND その次の記事（n+2）のiframeがバックグラウンドで読み込み中である
      AND 初回表示時は最初の記事のみ読み込む（先読みは初回表示完了後に開始）

### AC-4: プログレスバー削除

- [ ] WHEN 記事閲覧画面が表示された際
      THEN プログレスバーが表示されない
      AND PillNav（♡ + →）は従来通り表示される

### AC-5: 暗黙的フィードバック

- [ ] WHEN ユーザーが「次へ」ボタンをタップした際
      GIVEN 記事のスクロール深度と滞在時間に基づいて
      THEN 暗黙的なフィードバック（interest_level）が記録される
      AND 明示的なDislikeは記録されない

### AC-6: オブジェクトクラス全種対応

- [ ] WHERE オブジェクトクラスを表示する全コンポーネントにおいて
      THE SYSTEM SHALL Safe/Euclid/Keter/Thaumiel/Neutralized/Apollyon/Archonの7種 + Unknownに対応する
      AND 各クラスに固有のカラーが適用される

## 仕様変更履歴

### スクロール到達時の自動遷移を廃止

**変更日**: 2026-02-11
**対象Subtask**: 006-05-07 AC-7

**変更前**: スクロール90%到達で自動的にLike記録＋次記事へ遷移
**変更後**: スクロール到達では何も起きない。遷移は「次へ」ボタンタップのみ

**理由**: Story ACでは遷移トリガーは「次へ」ボタンタップのみと定義（AC-2, AC-5）。スクロール深度はフィードバックメタデータとして活用（「次へ」タップ時のinterest_level算出に利用）し、遷移トリガーとしては使用しない。

### スクロール検知方式の変更

**変更日**: 2026-02-11
**対象Subtask**: 006-05-06 AC-6, 006-02-02

**変更前**: postMessage方式（iframe内スクリプト注入 → parent.postMessage）
**変更後**: contentWindow直接アクセス方式（wiki-proxy同一オリジン → iframe.contentWindow.addEventListener）

**理由**: wiki-proxy経由の同一オリジン配信により、contentWindowへ直接アクセス可能。postMessage方式ではiframe側の送信スクリプトが未実装だった。

**補足（2026-02-16）**: wiki-proxyがDOM抽出方式に変更され、記事固有CSS/JSが保持されるようになった。スクロール検知方式（contentWindow直接アクセス）への影響はなし。
