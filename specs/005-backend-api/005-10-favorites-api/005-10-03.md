# Subtask 005-10-03: POST /favorites/:articleId エンドポイント

## 親 Story

[005-10: favorites API](./005-10.md)

## 概要

お気に入り追加 API（POST /favorites/:articleId）を実装する。
Repository に `add()` メソッド、Service に `addFavorite()` メソッドを追加し、
Hono ルーターに POST エンドポイントを登録する。

推薦エンジンは favorites テーブルを重み 2.0（最大）で参照するが、
現在 POST エンドポイントが存在しないため、お気に入り追加がDBに永続化されず
推薦スコアに反映されていない。本 Subtask でこの断絶を解消する。

## ステータス

- **status**: pending

## ユーザーストーリー

**ペルソナ**: SCPファン
**目的**: 気に入った記事をお気に入りとしてDBに永続化する
**価値**: 推薦エンジンが favorite シグナル（重み2.0）を反映し、より好みに合った推薦を受けられる
**理由**: お気に入り操作が推薦精度向上に直結する仕組みを完成させたい

> SCPファンとして、お気に入りに追加した記事をDBに永続化して、推薦エンジンが favorite シグナル（重み2.0）を反映できるようにしたい。なぜなら好みの記事に近い推薦を受けたいから。

## Acceptance Criteria（EARS記法）

### POST /favorites/:articleId

- [ ] AC-1: お気に入り追加エンドポイントを実装する
  - WHEN POST /favorites/:articleId をリクエストした際
  - GIVEN リクエストボディに有効な visitorId を含む場合
  - THEN favorites テーブルにレコードを挿入する
  - AND 201 Created を返す
  - AND レスポンス形式は `{ articleId: string, favoritedAt: string }`

- [ ] AC-2: 重複追加時は冪等に振る舞う
  - WHEN 既にお気に入り登録済みの articleId で POST した際
  - THEN 既存レコードをそのまま返す
  - AND 200 OK を返す（新規作成ではないため）

- [ ] AC-3: visitorId のバリデーションを行う
  - WHEN リクエストボディが空または visitorId が欠落した際
  - THEN 400 Bad Request を返す
  - AND RFC 7807 Problem Details 形式のエラーレスポンス

- [ ] AC-4: 存在しない visitorId に対して 404 を返す
  - WHEN 未登録の visitorId でリクエストした際
  - THEN 404 Not Found を返す
  - AND RFC 7807 Problem Details 形式のエラーレスポンス

### Repository / Service 層

- [ ] AC-5: Repository に add メソッドを追加する
  - WHEN `FavoritesRepository.add(visitorId, articleId)` を呼び出した際
  - THEN favorites テーブルに INSERT する
  - AND 挿入されたレコード（id, article_id, added_at）を返す

- [ ] AC-6: Service に addFavorite メソッドを追加する
  - WHEN `FavoritesService.addFavorite(visitorId, articleId)` を呼び出した際
  - THEN visitorId の存在確認を行う
  - AND 重複チェック後に Repository.add を呼び出す

  "/:articleId",

    const { visitorId } = c.req.valid("json");
