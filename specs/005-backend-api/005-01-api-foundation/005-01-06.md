# Subtask 005-01-06: 共通エラークラス定義

## 概要

api-server用の共通エラークラス（NotFoundError, ValidationError, OnboardingRequiredError）を定義し、error-handler.tsに統合する。

## ステータス

- **status**: pending

## ユーザーストーリー

**As a** API開発者
**I want** 意味のあるカスタムエラークラスを使用したい
**So that** ドメイン層で発生するエラーをRFC 7807形式で一貫してクライアントに返せる

## 背景・動機

以下のSubtaskで共通エラー型が必要とされている：

- 005-05-01 (recommend service): NotFoundError, OnboardingRequiredError
- 005-06-01 (feedback repository/service): NotFoundError
- 005-07-01 (onboarding service): NotFoundError, ValidationError

現状のerror-handler.tsはZodErrorとHTTPExceptionのみを処理しているが、ドメイン固有のビジネスエラーをより表現力豊かに扱うためのカスタムエラークラスが必要。

## Acceptance Criteria（EARS記法）

### AC-1: AppError ベースクラス

- [ ] WHEN AppErrorクラスを定義した際
      THEN Errorクラスを継承している
      AND type, title, status, detail, instanceプロパティを持つ
      AND toProblemDetails()メソッドでProblemDetails形式に変換できる

### AC-2: NotFoundError

- [ ] WHEN NotFoundErrorをインスタンス化した際
      GIVEN (resourceType: string, id: string)のコンストラクタ引数
      THEN statusが404である
      AND typeが"https://recommend-scp.dev/errors/not-found"である
      AND titleが"Resource Not Found"である
      AND detailが"{resourceType} with id '{id}' not found"形式である

### AC-3: ValidationError

- [ ] WHEN ValidationErrorをインスタンス化した際
      GIVEN (message: string)のコンストラクタ引数
      THEN statusが400である
      AND typeが"https://recommend-scp.dev/errors/validation-error"である
      AND titleが"Validation Error"である
      AND detailが渡されたmessageである

### AC-4: OnboardingRequiredError

- [ ] WHEN OnboardingRequiredErrorをインスタンス化した際
      GIVEN (visitorId: string)のコンストラクタ引数
      THEN statusが403である
      AND typeが"https://recommend-scp.dev/errors/onboarding-required"である
      AND titleが"Onboarding Required"である
      AND detailが"Visitor '{visitorId}' has not completed onboarding"形式である

### AC-5: error-handler.ts統合

- [ ] WHEN error-handler.tsでAppErrorインスタンスをキャッチした際
      THEN toProblemDetails()を呼び出してレスポンスを生成する
      AND 適切なHTTPステータスコードを返す
      AND Content-Typeが"application/problem+json"である

### AC-6: 既存動作の維持

- [ ] WHEN error-handler.tsが更新された際
      THEN ZodErrorのハンドリングが引き続き動作する
      AND HTTPExceptionのハンドリングが引き続き動作する
      AND 予期しないエラーのハンドリングが引き続き動作する

## 技術設計

### errors.ts

```typescript
import type { ProblemDetails } from "./problem-details";

const BASE_URI = "https://recommend-scp.dev/errors";

/**
 * アプリケーションエラーの基底クラス
 * RFC 7807 Problem Details形式に変換可能
 */
export class AppError extends Error {
  constructor(
    public readonly type: string,
    public readonly title: string,
    public readonly status: number,
    public readonly detail?: string,
    public readonly instance?: string
  ) {
    super(title);
    this.name = this.constructor.name;
  }

  toProblemDetails(): ProblemDetails {
    return {
      type: this.type,
      title: this.title,
      status: this.status,
      detail: this.detail,
      instance: this.instance,
    };
  }
}

/**
 * リソースが見つからない場合のエラー
 * @example new NotFoundError("Visitor", "abc-123")
 */
export class NotFoundError extends AppError {
  constructor(resourceType: string, id: string) {
    super(
      `${BASE_URI}/not-found`,
      "Resource Not Found",
      404,
      `${resourceType} with id '${id}' not found`
    );
  }
}

/**
 * バリデーションエラー
 * @example new ValidationError("At least 3 articles must be selected")
 */
export class ValidationError extends AppError {
  constructor(message: string) {
    super(`${BASE_URI}/validation-error`, "Validation Error", 400, message);
  }
}

/**
 * オンボーディング未完了エラー
 * @example new OnboardingRequiredError("abc-123")
 */
export class OnboardingRequiredError extends AppError {
  constructor(visitorId: string) {
    super(
      `${BASE_URI}/onboarding-required`,
      "Onboarding Required",
      403,
      `Visitor '${visitorId}' has not completed onboarding`
    );
  }
}
```

### error-handler.ts 更新箇所

```typescript
import { AppError } from "../lib/errors";

// createErrorHandler関数内に追加
export const createErrorHandler = (logger: Logger = defaultLogger): ErrorHandler => {
  return (error, c) => {
    // AppError: カスタムアプリケーションエラー（追加）
    if (error instanceof AppError) {
      return c.json(error.toProblemDetails(), error.status as ContentfulStatusCode, {
        "Content-Type": "application/problem+json",
      });
    }

    // 既存のZodError, HTTPException, 予期しないエラーのハンドリングは維持
    // ...
  };
};
```

### インターフェース整合性

既存の`problem-details.ts`のErrorTypesと整合：

| ErrorTypes定数      | エラークラス            | 用途                   |
| ------------------- | ----------------------- | ---------------------- |
| VALIDATION_ERROR    | ValidationError         | バリデーション失敗     |
| NOT_FOUND           | NotFoundError           | リソース未発見         |
| ONBOARDING_REQUIRED | OnboardingRequiredError | オンボーディング未完了 |
| INTERNAL_ERROR      | （なし、汎用Error用）   | 予期しないエラー       |
