# Subtask 007-01-01: CIマイグレーション自動実行

## 概要

GitHub ActionsでSupabase CLIを使用し、mainブランチへのマージ時にデータベースマイグレーションを自動実行する。

## ユーザーストーリー

```
AS A 開発者
I WANT mainブランチへのマージ時にDBマイグレーションが自動適用される
SO THAT 手動実行の漏れを防ぎ、デプロイの一貫性を担保できる
```

## Acceptance Criteria（EARS記法）

### AC-1: マイグレーション自動実行

- [ ] WHEN mainブランチにプッシュされた際
      GIVEN supabase/migrations/ 配下にSQLファイルが存在する場合
      THEN CIはSupabase CLIを使用してマイグレーションを実行する
      AND 実行結果をGitHub Actions Summaryに出力する

### AC-2: 認証情報の安全な管理

- [ ] WHEN CIがSupabaseに接続する際
      GIVEN SUPABASE_ACCESS_TOKEN と SUPABASE_PROJECT_REF が設定されている場合
      THEN CIはSecrets経由で認証情報を取得する
      AND 認証情報がログに出力されないことを保証する

### AC-3: PRでのドライラン

- [ ] WHEN PRがオープンされた際
      GIVEN supabase/migrations/ に変更がある場合
      THEN CIはマイグレーションのドライラン（検証のみ）を実行する
      AND 適用予定のマイグレーション一覧を表示する

### AC-4: エラーハンドリング

- [ ] WHEN マイグレーション実行が失敗した際
      GIVEN ネットワークエラーまたはSQL構文エラーが発生した場合
      THEN CIはエラー詳細を出力する
      AND ジョブを失敗ステータスで終了する

### AC-5: 冪等性の確保

- [ ] WHEN 既に適用済みのマイグレーションが存在する際
      GIVEN 同じマイグレーションファイルが再実行された場合
      THEN Supabase CLIはスキップして次に進む
      AND エラーとならない

## 技術設計

### ワークフローファイル

**ファイル**: `.github/workflows/migrate.yml`

```yaml
name: Database Migration

on:
  push:
    branches: [main]
    paths:
      - 'supabase/migrations/**'
  pull_request:
    branches: [main]
    paths:
      - 'supabase/migrations/**'

jobs:
  migrate:
    name: Run Migrations
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Supabase CLI
        uses: supabase/setup-cli@v1
        with:
          version: latest

      - name: Link Project
        run: supabase link --project-ref ${{ secrets.SUPABASE_PROJECT_REF }}
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}

      # PRの場合はドライラン
      - name: Dry Run (PR only)
        if: github.event_name == 'pull_request'
        run: |
          echo "## Migration Dry Run" >> $GITHUB_STEP_SUMMARY
          supabase db push --dry-run 2>&1 | tee migration-preview.txt
          cat migration-preview.txt >> $GITHUB_STEP_SUMMARY
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}

      # mainへのpushの場合は実行
      - name: Run Migrations (main only)
        if: github.ref == 'refs/heads/main'
        run: |
          echo "## Migration Result" >> $GITHUB_STEP_SUMMARY
          supabase db push 2>&1 | tee migration-result.txt
          cat migration-result.txt >> $GITHUB_STEP_SUMMARY
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}
```

### 必要なSecrets

| Secret名 | 用途 | 取得方法 |
|---|---|---|
| `SUPABASE_ACCESS_TOKEN` | Supabase API認証 | Dashboard > Account > Access tokens |
| `SUPABASE_PROJECT_REF` | プロジェクト識別子 | Dashboard > Project Settings > General |

### 成果物

| ファイル | 内容 |
|---|---|
| `.github/workflows/migrate.yml` | マイグレーション用ワークフロー |
| `supabase/config.toml` | Supabase CLI設定（必要に応じて） |

## テストケース

### 正常系

- [ ] mainブランチへのpush時にマイグレーションが実行される
- [ ] PR時にドライラン結果がSummaryに表示される
- [ ] 適用済みマイグレーションはスキップされる

### 異常系

- [ ] 認証エラー時にジョブが失敗ステータスで終了する
- [ ] SQL構文エラー時にエラー詳細が出力される
- [ ] migrations変更なしの場合はジョブがスキップされる

## 非機能要件

| カテゴリ | 要件 |
|---|---|
| **セキュリティ** | Secretsの漏洩防止 |
| **信頼性** | ネットワーク障害時はSupabase CLI内部でリトライ |
| **可観測性** | 実行ログをGitHub Actions Summaryに出力 |

## 依存関係

- `supabase/migrations/` にマイグレーションファイルが存在すること
- GitHub SecretsにSUPABASE_ACCESS_TOKEN, SUPABASE_PROJECT_REFが設定されていること

## 実装メモ

- Supabase CLIは `supabase/setup-cli@v1` アクションでインストール
- `supabase db push` は未適用のマイグレーションのみ実行（冪等）
- `--dry-run` オプションで実行せずにプレビュー可能
