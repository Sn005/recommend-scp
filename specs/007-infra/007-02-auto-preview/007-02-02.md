# Subtask 007-02-02: Hono API統合

## 概要

既存のHono APIをNext.js API Routesにマウントし、Vercel Edge Runtimeで動作させる。

## ユーザーストーリー

```
AS A フロントエンド開発者
I WANT Vercelプレビューで `/api/*` にアクセスするとHono APIが応答する
SO THAT 単一URLでフロントエンドとAPIの両方を確認できる
```

## 背景

現在の構成:

- `apps/api-server/src/app.ts` で `createApp(supabase)` がHonoアプリを生成
- `apps/web/src/shared/lib/api-client.ts` で `NEXT_PUBLIC_API_URL` を使用

ハイブリッド方式:

- ローカル: `NEXT_PUBLIC_API_URL=http://localhost:3001`（api-server直接）
- Vercel: `NEXT_PUBLIC_API_URL=/api`（Next.js API Routes経由）

## 技術仕様

### 新規ファイル: `apps/web/src/app/api/[...route]/route.ts`

```typescript
import { handle } from "@hono/vercel";
import { createApp } from "@recommend-scp/api-server/app";
import { createClient } from "@supabase/supabase-js";

// Supabase クライアント初期化（Edge Runtime用）
const supabase = createClient(process.env.SUPABASE_URL!, process.env.SUPABASE_SERVICE_ROLE_KEY!);

// Hono app 生成
const app = createApp(supabase);

// Vercel Edge Handler
export const GET = handle(app);
export const POST = handle(app);
export const PUT = handle(app);
export const DELETE = handle(app);
export const PATCH = handle(app);

// Edge Runtime指定
export const runtime = "edge";
```

### パッケージ追加

```bash
pnpm --filter web add @hono/vercel
```

### api-serverのエクスポート変更

`apps/api-server/package.json` に exports を追加:

```json
{
  "exports": {
    "./app": "./src/app.ts"
  }
}
```

### 環境変数の使い分け

| 環境     | NEXT_PUBLIC_API_URL     | 接続先                    |
| -------- | ----------------------- | ------------------------- |
| ローカル | `http://localhost:3001` | api-server (Node.js)      |
| Vercel   | `/api`                  | Next.js API Routes (Edge) |

## 注意事項

### Edge Runtime制約

- Node.js固有のAPIは使用不可（fs, path等）
- 現在のHono APIはEdge互換（Supabase JS, OpenAI SDK）

### CORSについて

- 同一オリジンのため、Vercel環境ではCORS不要
- ローカルではapi-serverのCORSミドルウェアが処理
