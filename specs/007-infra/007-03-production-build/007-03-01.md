# Subtask 007-03-01: CIビルド検証ステップ追加

## 概要

GitHub Actions の CI ワークフロー（`ci.yml`）に `pnpm build` ステップを追加し、全パッケージの本番ビルドがPR・pushのたびに検証されるようにする。

## ユーザーストーリー

```
AS A 開発者
I WANT CIで本番ビルドが自動検証される
SO THAT ビルド退行をマージ前に検知し、デプロイ失敗を未然に防げる
```

## Acceptance Criteria（EARS記法）

### AC-1: ビルドステップの追加

- [ ] WHEN CI ワークフローが実行された際
      GIVEN PRまたはmainへのpushがトリガーとなった場合
      THEN `pnpm build` ステップが type-check の後に実行される
      AND 全パッケージ（shared, api-types, api-server, web）のビルドが実行される

### AC-2: ビルド失敗時のCI失敗

- [ ] WHEN いずれかのパッケージのビルドが失敗した際
      THEN CI ジョブが失敗ステータスで終了する
      AND エラー詳細がログに出力される

### AC-3: 既存ステップとの共存

- [ ] WHEN ビルドステップが追加された後
      GIVEN 既存の lint, format:check, type-check, test ステップが存在する場合
      THEN 全ての既存ステップが引き続き正常に動作する
      AND ステップ実行順序は lint → format:check → type-check → build → test となる

## 技術設計

### 変更対象ファイル

| ファイル                   | 変更内容                    |
| -------------------------- | --------------------------- |
| `.github/workflows/ci.yml` | `pnpm build` ステップを追加 |

### 実行順序

```
Lint → Format Check → Type Check → Build → Test with Coverage
```

**Build を Type Check の後、Test の前に配置する理由:**

- Type Check で型安全性を確認してからビルド
- ビルド成果物がテストに必要な場合に備えて Test の前に実行

### 追加するステップ

```yaml
- name: Build
  run: pnpm build
```

## テストケース

### 正常系

- [ ] `pnpm build` で全パッケージのビルドが成功する
- [ ] ビルド後も既存のテストが全てパスする

### 異常系

- [ ] ビルドエラーがある場合にCIが失敗ステータスとなる
