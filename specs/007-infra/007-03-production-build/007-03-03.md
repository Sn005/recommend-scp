# Subtask 007-03-03: packages/sharedビルド整備

## 概要

`packages/shared` にtsupによるビルドステップを追加し、トランスパイル済みJavaScriptと型定義ファイルを `dist/` に出力する。これにより、任意のNode.jsランタイムから直接importできるようにする。

## ユーザーストーリー

```
AS A 開発者
I WANT packages/shared がビルド済みJSを出力する
SO THAT Node.jsランタイムから直接importでき、他パッケージのビルド構成に依存しない
```

## 背景・課題

現行の `packages/shared` は以下の状態:

- `tsconfig.json` に `noEmit: true` — 型チェックのみ、JS出力なし
- `exports` フィールドが `.ts` ソースファイルを直接指している
- Next.js（`transpilePackages`）や `tsx` 経由では動作するが、純粋なNode.jsランタイムでは読み込めない
- 他パッケージが shared をimportする場合、各パッケージ側でトランスパイルを担保する必要がある

## Acceptance Criteria（EARS記法）

### AC-1: tsup導入とビルド設定

- [ ] WHEN `pnpm --filter shared build` を実行した際
      THEN tsup が shared のソースをトランスパイルし `dist/` にESM形式のJSファイルを出力する
      AND 各 exports エントリに対応するファイルが `dist/` に生成される

### AC-2: 型定義の出力

- [ ] WHEN ビルドが完了した際
      THEN `dist/` に `.d.ts` 型定義ファイルが出力される
      AND 他パッケージから型推論が正常に機能する

### AC-3: exports フィールドの更新

- [ ] WHEN `package.json` の `exports` フィールドが更新された際
      THEN 各エントリが `dist/` 配下のビルド済みファイルを指す
      AND `types` 条件で `.d.ts` ファイルを、`import` 条件でビルド済みJSを指す
      AND 開発時のソース参照も `source` 条件で維持される

### AC-4: Turbo ビルド順序の維持

- [ ] WHEN `pnpm build` でモノレポ全体をビルドした際
      GIVEN turbo.json で `"dependsOn": ["^build"]` が設定されている場合
      THEN shared が api-server, web より先にビルドされる
      AND 全パッケージのビルドが正常に完了する

### AC-5: 既存テスト・消費者の維持

- [ ] WHEN ビルド設定を変更した後
      THEN shared 自体のテストが全てパスする
      AND api-server のテストが全てパスする
      AND web のビルド（`next build`）が正常に完了する

## 技術設計

### 変更対象ファイル

| ファイル                         | 変更内容                                   |
| -------------------------------- | ------------------------------------------ |
| `packages/shared/package.json`   | build スクリプト追加、exports 更新         |
| `packages/shared/tsconfig.json`  | 変更なし（型チェック用に `noEmit` を維持） |
| `packages/shared/tsup.config.ts` | 新規: tsup設定ファイル                     |

### tsup 設定案

```typescript
import { defineConfig } from "tsup";

export default defineConfig({
  entry: [
    "src/lib/env.ts",
    "src/lib/supabase.ts",
    "src/types.ts",
    "src/embedding/index.ts",
    "src/tagging/index.ts",
    "src/search/index.ts",
    "src/onboarding/index.ts",
    "src/storage/index.ts",
    "src/storage/server.ts",
    "src/recommendation/index.ts",
  ],
  format: ["esm"],
  target: "es2022",
  outDir: "dist",
  clean: true,
  dts: true,
  sourcemap: true,
  external: ["@supabase/supabase-js", "openai", "dotenv", "find-up"],
});
```

### package.json exports 更新案

```json
{
  "exports": {
    "./lib/env": {
      "types": "./dist/lib/env.d.ts",
      "import": "./dist/lib/env.js",
      "source": "./src/lib/env.ts"
    },
    "./lib/supabase": {
      "types": "./dist/lib/supabase.d.ts",
      "import": "./dist/lib/supabase.js",
      "source": "./src/lib/supabase.ts"
    },
    "./types": {
      "types": "./dist/types.d.ts",
      "import": "./dist/types.js",
      "source": "./src/types.ts"
    }
  }
}
```

（全エントリに同パターンを適用）

### ビルド前後の比較

| 項目        | 現状                      | 変更後                 |
| ----------- | ------------------------- | ---------------------- |
| 出力        | なし（`noEmit`）          | `dist/` にJSファイル   |
| exports     | `.ts` ソース直接          | `dist/` のビルド済みJS |
| 型定義      | ソースから直接推論        | `.d.ts` ファイル       |
| Node.js互換 | tsx/transpilePackages必須 | `node` で直接import可  |
