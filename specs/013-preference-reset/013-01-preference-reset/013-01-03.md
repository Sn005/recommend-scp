# Subtask 013-01-03: フロントエンドUI（ドロワー・確認ダイアログ）

## 概要

ドロワーメニューに「推薦をリセット」項目を追加し、確認ダイアログによる誤操作防止とリセット後のオンボーディングリダイレクトを実装する。

**status**: completed

## ユーザーストーリー

**As a** SCP推薦アプリのユーザー
**I want** ドロワーメニューから嗜好データをリセットしたい
**So that** 安全にリセット操作を行い、新しいジャンルの記事に出会える

## Acceptance Criteria（EARS記法）

### AC-1: ドロワーメニュー表示

- [x] WHEN ユーザーがドロワーメニューを開いた際
      THEN 「閲覧履歴」の下に区切り線が表示される
      AND 区切り線の下に「推薦をリセット」メニュー項目が表示される
      AND リセットアイコン（refresh-cw）が表示される

### AC-2: 確認ダイアログ表示

- [x] WHEN ユーザーが「推薦をリセット」をタップした際
      THEN 確認ダイアログが表示される
      AND ダイアログには以下が含まれる: - タイトル: 「推薦をリセット」- 説明: リセット内容の説明（嗜好データが初期化されること）- 保持データの説明（お気に入り・閲覧履歴は保持）- 「リセットする」ボタン（破壊的アクション: 赤系カラー）- 「キャンセル」ボタン

### AC-3: キャンセル操作

- [x] WHEN ユーザーが「キャンセル」をタップした際
      THEN ダイアログが閉じる
      AND データは変更されない

- [x] WHEN ユーザーがダイアログ外をタップした際
      THEN ダイアログが閉じる
      AND データは変更されない

### AC-4: リセット実行

- [x] WHEN ユーザーが「リセットする」をタップした際
      THEN `POST /visitors/reset` APIが呼び出される
      AND ローディング状態が表示される（ボタン無効化 + スピナー）
      AND 成功後、ドロワーが閉じる
      AND `/onboarding` にリダイレクトされる

### AC-5: エラーハンドリング

- [x] WHEN リセットAPIが失敗した際
      THEN エラーメッセージがダイアログ内に表示される
      AND ダイアログは閉じない（リトライ可能）

### AC-6: 二重送信防止

- [x] WHILE リセットAPIを呼び出し中
      THE SYSTEM SHALL 「リセットする」ボタンを無効化する
      AND 追加のAPI呼び出しを防止する

```typescript
// useResetPreference.ts
export const useResetPreference = () => {
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  const reset = async (visitorId: string) => {
    setIsLoading(true);
    setError(null);
    try {
      const res = await api.visitors.reset.$post({
        json: { visitorId },
      });
      if (!res.ok) throw new Error("リセットに失敗しました");
      return true;
    } catch {
      setError("リセットに失敗しました。もう一度お試しください。");
      return false;
    } finally {
      setIsLoading(false);
    }
  };

  return { reset, isLoading, error };
};
```
