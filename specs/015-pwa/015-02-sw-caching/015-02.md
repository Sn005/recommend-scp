# Story 015-02: Service Worker キャッシュ戦略

## 概要

Service Worker にWorkboxベースのキャッシュ戦略を導入し、wiki-proxy記事HTMLのオフライン閲覧と高速表示を実現する。

**status**: completed

## ユーザーストーリー

**As a** SCPicksの利用者
**I want** 一度閲覧した記事がキャッシュされ、即座に表示されるようにしたい
**So that** 2回目以降の記事表示が高速になり、オフライン環境でも閲覧済み記事を読める

## Story-level Acceptance Criteria

- [x] wiki-proxy記事HTMLがService Workerでキャッシュされる
- [x] キャッシュ済み記事は即座に表示される（Stale-While-Revalidate）
- [x] サブリソース（CSS/画像/JS）もキャッシュされオフラインで記事が正常表示される
- [x] キャッシュは最終アクセスから3ヶ月で自動パージされる
- [x] ストレージ圧迫時に自動的にLRUパージされる
- [x] 既存機能に影響がない

## 背景

### 設計判断（/clarify セッションで確定）

| 項目             | 決定                              | 理由                            |
| ---------------- | --------------------------------- | ------------------------------- |
| ライブラリ       | Workbox（CDN importScripts）      | 車輪の再発明回避、battle-tested |
| 記事HTML戦略     | Stale-While-Revalidate            | 即時表示＋Wiki記事の鮮度維持    |
| サブリソース戦略 | Cache-first                       | CSS/画像は変更頻度が低い        |
| 保持期限         | 3ヶ月                             | ユーザーの再訪サイクルを考慮    |
| パージ           | purgeOnQuotaError + maxAgeSeconds | Workbox ExpirationPlugin内蔵    |

### キャッシュアーキテクチャ

```
┌──────────────────────────────────────────────────────┐
│  Service Worker (sw.js)                              │
│                                                      │
│  Workbox (CDN importScripts)                         │
│  ├── workbox.routing                                 │
│  ├── workbox.strategies (SWR, CacheFirst)            │
│  └── workbox.expiration (ExpirationPlugin)           │
│                                                      │
│  Cache API (Workbox管理)                             │
│  ├── scp-articles-v1      (wiki-proxy HTML)          │
│  └── scp-sub-resources-v1 (CSS/画像/JS)             │
│                                                      │
│  IndexedDB (Workbox ExpirationPlugin が自動管理)     │
│  └── タイムスタンプ + LRU追跡                        │
└──────────────────────────────────────────────────────┘
```
